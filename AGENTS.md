# Курсовая: оценка кредитного риска

Исходники определяют предметный анализ, инструменты собирают и исполняют его. Итоговая сборка находится в `build/`, временные материалы — в `tmp/`

## Окружение

Все команды выполняются из корня курсовой. Используйте Python 3.13+ с зависимостями из `pyproject.toml`. `requirements.lock` — точный снимок установленных версий проверенного окружения, включая транзитивные зависимости; это не универсальный кроссплатформенный lock с хешами

При создании окружения:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
source .venv/bin/activate
```

Дальше `python` означает интерпретатор этого окружения.

Статистика проекта: `python -m tooling.project_stats`. Команда выводит и сохраняет в `project.stats.txt` в корне пять показателей: суммарный размер файлов (включая датасет), число файлов, число notebooks, строки кода и строки текста. Учитываются файлы Git и новые файлы, не исключённые через `.gitignore`. Код считается в `.py` и кодовых ячейках notebooks; текст — в `.md`, `.txt`, Markdown- и raw-ячейках. Пустые строки и комментарии учитываются, результаты выполнения ячеек в число строк не входят. Размер — сумма размеров файлов, без служебных данных Git. Оба файла статистики исключены из подсчёта. `project.stats.txt`, `build/solution.stats.txt`, обе версии notebook и копия CSV в `build/` версионируются в Git.

## Сборка

Pre-commit хук автоматически пересчитывает оба файла статистики по файлам, подготовленным к коммиту, и добавляет отчёты в коммит. Он читает обе сохранённые версии notebook из индекса во временной папке, без пересборки, выполнения ячеек и изменения локальных notebooks в `build/`. Перед коммитом изменений исходников пересоберите и выполните notebook, затем добавьте обе версии сборки в индекс. Нужна `.venv` с зависимостями проекта. Для подключения хука после клонирования выполните `git config core.hooksPath .githooks`.

```bash
python -m tooling.build.builder
# build/solution.unexecuted.ipynb
```

Сборщик создаёт автономный notebook без результатов выполнения (`solution.unexecuted.ipynb`) и копирует `dataset/credit_risk_dataset.csv` рядом с ним в `build/` (при `--output` — в папку указанного файла). Другие форматы ещё не реализованы. `--output /путь/файл.ipynb` задаёт базовое имя: неисполненная версия сохраняется как `файл.unexecuted.ipynb`. Запись внутрь `src/` запрещена

Рядом со сборкой создаётся `solution.stats.txt`: сначала две строки размера — неисполненной и исполненной версий, затем общие показатели без повторов: число ячеек, строки кода, строки текста, число слов в текстовых ячейках, минимум и максимум строк в кодовой ячейке. Пустые строки и комментарии учитываются. Если исполненной версии ещё нет, её размер не выводится. Команда выполнения обновляет отчёт после сохранения результатов.

В `project.json` указаны только входной notebook (`entry`), итоговый файл (`output`) и CSV (`dataset`). Сборщик раскрывает включения, сохраняя порядок ячеек, текст, формулы и вложения. Он не выполняет код. Для готового файла с заново выполненными расчётами:

```bash
python -m tooling.execution.runner
# build/solution.ipynb — выполненный notebook
```

Команда сохраняет неисполненную сборку в `build/solution.unexecuted.ipynb`, копирует CSV рядом и выполняет notebook в чистом kernel из папки сборки. Исполненную версию сохраняет в `build/solution.ipynb`; при ошибке её предыдущая версия не перезаписывается. Требуются локальные порты Jupyter. При сдаче приложите `credit_risk_dataset.csv` рядом с notebook.

## Исходники и включения

Исходники находятся в `src/`, точка входа — `src/_index.ipynb`. Отдельно исходные notebooks не запускаются: редактируем их, собираем и выполняем итоговый notebook.

Включение занимает отдельную кодовую ячейку с одной директивой:

```python
# include: 03_analysis/_index.ipynb
```

Сборщик вставляет ячейки указанного notebook и рекурсивно раскрывает вложенные включения. Путь считается относительно notebook с директивой.

Для статической вставки Python-файла используется та же команда:

```python
# include: _code/training_plots.py
```

Содержимое `.py` становится обычной кодовой ячейкой. В результате нет директив, загрузчиков или проектных импортов. Повторные включения допустимы; циклические включения, отсутствующие файлы и неподдерживаемые расширения останавливают сборку. Остальные ячейки переносятся как есть.

`src/_setup.ipynb` содержит подготовку зависимостей, вспомогательные функции и общие настройки отображения. Он включается из `src/_index.ipynb` сразу после оглавления. Это обычные ячейки, они тоже входят в сборку. Команда установки не закрепляет версии и не устанавливает IPython, который предоставляет ядро Jupyter/Colab. Точные версии для локального окружения остаются в `pyproject.toml`; результаты на других версиях библиотек могут отличаться.

Сборщик копирует `credit_risk_dataset.csv` рядом с итоговым notebook. Запускайте готовый notebook из этой папки. В Google Colab загрузите CSV через панель файлов в рабочую папку среды выполнения, обычно `/content/`. Автоматического скачивания данных нет.

## Содержание завершённой работы

Все семь этапов заполнены. Общий EDA и фиксированная очистка исторически сделаны до случайного стратифицированного разбиения 70/15/15. Дополнительный анализ — только train. Pipeline обучает медианы, моду, масштабирование и кодирование только на train. Loan grade использует порядок A–G, бинарные признаки считаются номинальными. Сравниваются Dummy, логистическая регрессия, лес и гистограммный бустинг; модель выбирается по validation AP, порог — по validation F2. После фиксации test используется для итоговых метрик, bootstrap-интервалов и графиков, без донастройки.

В этапе 7 отдельная таблица содержит только выводы об итоговой модели: входы, обработку, порог, качество и применение. Накопленные выводы EDA там не повторяются. Это учебный эксперимент на одном Kaggle-разбиении; реальные условия кредитования, внешняя валидация и мониторинг описаны как ограничения и дальнейшая работа. Сервис не развёртывается. Итоговый notebook содержит код и результаты, проектные Python-импорты для его запуска не нужны.

Описания столбцов и наши пояснения в этапе 1 хранятся в простых HTML-таблицах Markdown-ячеек. В Python остаются загрузка данных, вычисление диапазонов и определение типов признаков.

## Таблица выводов

В начале этапа 3 `conclusions = empty_findings()` создаёт пустую общую таблицу Pandas. После подэтапов `update_findings` добавляет записи `(id, вывод, решение)` и принимает список `remove` для закрытых записей. Постоянный id позволяет уточнить вывод без дублирования актуальной версии

`Метка` принимает `new`, `removed` или пустую строку. `findings_view(conclusions)` показывает всю таблицу, `findings_view(conclusions, only_new=True)` — только новые выводы. Новые строки выделяются зелёным и знаком «+», удаляемые — красным и знаком «−». На следующем обновлении удаляемые строки исчезают, а предыдущие новые становятся обычными. В коде метки хранятся отдельно от текста

Маленькие обновления находятся прямо после соответствующего анализа. Общие функции обработки и оформления — в соседнем `_code/findings.py`.

## Пошаговое выполнение анализа

Этап 3 отдельно включает `04_hypothesis_checks.ipynb` с проверкой гипотез и `05_model_specification.ipynb` с выбором спецификаций

В этапе 4 обработка показана по шагам: состав признаков и выборки, числовые признаки, номинальные категории, общая цепочка. Короткие определения преобразований находятся прямо рядом с пояснениями в notebook. Проверка новых заявок вынесена в `_code/prepare_applications.py` и подключается перед локальным прогнозом

Проверки гипотез, обучение и итоговая оценка также разделены на пояснения и соответствующие вычисления. Крупные блоки построения диагностических графиков и итоговой таблицы выводов остаются в соседней `_code/`

В спецификации фиксированы 9 входных признаков: исключены `loan_grade` (сильная связь со ставкой, сохраняем числовую ставку) и `loan_percent_income` (производный от суммы и дохода, часть значений не согласуется с отношением). Грейд и доля остаются в исходной таблице для EDA, но не входят в обучение и новые заявки. Порядковое кодирование в предобработке отсутствует. Наборы признаков между собой не сравниваем.
